## 桌码与现有商城的关联核验

桌码只包含项目、桌位和场景，不包含菜单或商品 ID。菜单调整、重新绑定、商品价格和上下架变化沿用同一桌码。每项目提供 8 条桌码和 6 条菜单演示数据；菜单复用已有商品、服务及分类。

| 场景 | 核验内容 | 结果 |
| --- | --- | --- |
| 后台维护 | 菜单单商家约束、商品勾选、分组排序/显隐、菜单价、菜单/桌码启停 | 自动测试通过；商家 PC 页面和二维码预览已检查 |
| 原码更新菜单 | 测试时把咖啡菜单价保存为 ¥19.99，再用同一个静态桌码进入 | 菜单、规格弹层、购物车及确认订单均显示 ¥19.99；此为本地验收数据，发布的默认菜单不写入该测试覆盖价 |
| 实体商品 | 复用现有规格、数量、加购物车、确认订单与付款流程 | 菜单价带入真实报价；已配置会员价优先；订单保存 table_id、scene、order_type、menu_id 及商家分类 |
| 预约服务 | 扫码菜单进入原日期、场地、时段选择，独立创建预约单并占用资源 | 不允许放入实体购物车或混合提交；预约价格和桌位信息保持到确认及提交 |
| 普通商城与桌码隔离 | 扫码时保留已有普通订单草稿、原价格与原桌位；不同桌、不同场景分别保存购物车 | 普通单不继承菜单价；扫码加购不污染普通草稿；提交只清理该结算来源的已选购物车行 |
| 离开扫码再付款 | 从扫码菜单形成的实体或预约结算带显式场景信息 | 继续按该订单来源校验和报价，不依赖当前浏览页面 |
| 无效售卖范围 | 跨项目、已停用桌码/菜单、已下架商品、旧菜单失效 | 拦截失效商品和混合交易，保留错误提示 |
