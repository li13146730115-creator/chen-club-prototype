# V0.11 原型调整实现计划

> 面向 AI 代理的工作者：使用 subagent-driven-development 分模块实现与审查，逐项记录验证证据。

目标：落实 V0.11 的扫码菜单、权益卡、预约人数、棕色主题、活动月历及邀请函要求。

架构：保留现有商城交易、价格、卡券和预约状态；通过 v14 独立扩展文件在现有模块之后注册。新内容沿用现有商家配置与活动资料，运营和商家都有维护入口。静态原型的邀请链接携带公开邀请内容，不携带核销码、手机号和原会员身份。

技术栈：无构建 HTML/CSS/JavaScript，node:test 与浏览器验收。

- [x] 扫码点单（v14-scan.js/css、tests/v14-scan.test.cjs）：扩充维护中的菜单类别；单规格直接加减，多规格弹层；移除页面查看购物车，保留底部导航。保留项目桌位、菜单价、SKU和普通购物车隔离。结算不展示店铺名称。
- [x] 活动和邀请函（v14-experience.js/css、tests/v14-experience.test.cjs）：首页/服务入口→按月日历→活动详情→现有预约；活动时间、关联服务、地址由后台维护。凭证生成分享邀请→公开邀请查看→地址地图导航，核销码和原会员隐私不进入分享链接。接收人有当前昵称时显示昵称，未登录显示来宾。
- [x] 预约人数（v14-capacity.js/css、tests/v14-capacity.test.cjs）：商家服务添加/编辑与运营对应入口维护是否展示人数及容量；泳池按当前人数/饱和人数显示，日期、资源、时段刷新人数；取消与退款释放占用，提交阻止超容量。
- [x] 权益和主题（v14-owner.js、v14-theme.css）：权益方图垂直居中，去价格、赠送改权益、自购保留；对齐后台卡券预览。以现有商城棕色为基准统一主色，保留页面布局。
- [x] 集成：index.html 接入；为行为变化先编写失败测试；运行各模块测试，再全量测试；逐项浏览375×812和1440×900，确认关联后台入口。
- [x] 文档与发布：生成逐项核验记录，同步离线包，发布GitHub Pages，核对部署版本和线上截图。

检验重点：多规格SKU加减与库存；跨桌位和项目隔离；人数满额和取消释放；日历跨月与下架活动；分享数据不可用于核销；卡券真实余额/价格计算不因展示调整而变化。
