## 券库存与发放接口

```js
Club.v11Membership.grantCoupons(memberId, templateId, quantity = 1, {
  automatic: false,
  planId: undefined
});
```

- 新模板：`inventoryMode='stock'`，`quantity` 为总库存，`stock` 为尚未发放库存；编辑库存保留既有已发放数量。
- 新资产：`remaining`／`total`／`quantity` 保存该批券张数；`unit='张'`、`couponUnit='张'`、`usePerCoupon=1`。兑换时每张对应一个商品或一次具体服务规格。原金额字段与退款恢复逻辑不变。
- 自动发放：绑定、发布时每个 `会员 + 会籍 + 券模板` 发一张，台账幂等。手动推送可以再发多张，单独留存来源和台账。
- 有效期：发放快照、会员编辑、卡券读取同步至 `member.expiry`，不再按发放后天数另行截止。
- 余额扣减、代客使用张数和退款继续使用 `ASSET:<id>` 与原 `remaining` 模型；跨模块可继续调用 `A.v07.coupons`、`A.v10.issued`。

## 当前边界

- 历史已发券保留原次数／小时单位和余额，避免修改既有核销及退款语义；新建券采用库存张数模型。历史模板列表会标记“历史券”，可编辑后转入新库存模型。
- 自动发放遇到库存不足会跳过并提示，补库存后发布即可按台账补发未收到的绑定；手动超库存、跨店、不适用会籍或过期会员发券直接拒绝，不产生部分写入。
- `SOURCE-P***` 属于原始资料价目，包含“500 元/位”“待确认”等文本，保留原资料，不作为新的可购买 SKU；A03 的可配置商品来自既有商城可售目录，并覆盖全部商家／会所。
- 本子任务未调用浏览器、未提交 Git、未修改 index 或共享文件。父任务接入脚本和 CSS 后统一做浏览器与发布验证。
